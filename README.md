# Tracker — Система управления офисным пространством и инфраструктурой

Tracker — это веб-платформа для комплексного управления рабочим пространством, интерактивными схемами этажей, заявками на обслуживание, учетом материально-технического оборудования и бронированием переговорных комнат.

## Ключевые возможности

* **Интерактивные карты офиса:** Векторные SVG-планы этажей с отображением стен, зон, переговорных, рабочих мест сотрудников и их текущего статуса.
* **Канбан-трекер задач:** Управление заявками и инцидентами со статусами, приоритетами, матрицей критичности (S1–S4), фильтрацией и прикреплением скриншотов.
* **Real-time синхронизация:** Мгновенное обновление карточек задач, бронирований и статусов оборудования через Server-Sent Events (SSE) без перезагрузки страниц.
* **Учет оборудования (МТО):** Учет серийных и инвентарных номеров, привязка техники к столам и сотрудникам, пакетный ввод, OCR-распознавание накладных (УПД) и печать термоэтикеток со штрихкодами.
* **Бронирование переговорных:** Интерактивное расписание, мгновенное бронирование в 1 клик и специальный адаптивный интерфейс для настенных планшетов переговорных комнат с защитой от продления снаружи.
* **Сетевой мониторинг (Пингер):** Фоновый опрос доступности оборудования и компьютеров по IP-адресам с фиксацией онлайн-статуса и историей проверок.
* **Встроенный конструктор этажей:** Графический редактор для создания новых этажей, черчения стен, расстановки столов и нанесения подписей помещений.
* **Адаптивный дизайн и темы:** Полноценная поддержка мобильных телефонов, планшетов, десктопов, а также переключение темной и светлой темы.

## Архитектура и стек технологий

```
┌─────────────────────────────────────────────────────────────┐
│                      Client Layer                           │
│  Vanilla JS (ES6+) · Custom CSS (Dark/Light) · SVG Canvas   │
│                 Server-Sent Events (SSE)                    │
└──────────────────────────────▲──────────────────────────────┘
                               │ HTTP / SSE (Port 1111)
┌──────────────────────────────▼──────────────────────────────┐
│                    Go Backend (Tracker)                    │
│  net/http Router · GORM ORM · HMAC-SHA256 Auth Middleware   │
│            SSE Hub · Background Pinger Service              │
└──────────────────────────────▲──────────────────────────────┘
                               │ PostgreSQL Protocol (Port 5432)
┌──────────────────────────────▼──────────────────────────────┐
│                    PostgreSQL 16 Database                   │
│   Floors · Workplaces · Employees · Tasks · Inventory ...   │
└─────────────────────────────────────────────────────────────┘
```

* **Backend:** Go 1.24+ (`net/http` с pattern-маршрутизацией, GORM, bcrypt, crypto/hmac, godotenv).
* **Database:** PostgreSQL 16.
* **Frontend:** Чистый JavaScript без тяжелых фреймворков, CSS3 переменные, SVG DOM API.
* **Контейнеризация:** Двухэтапный Dockerfile (Multi-stage на базе Alpine) и Docker Compose.

## Быстрый запуск через Docker Compose

### Требования
* Установленный Docker (версия 20.10+) и Docker Compose v2.

### Запуск одной командой
1. Склонируйте репозиторий и перейдите в каталог проекта:
   ```bash
   git clone <url_репозитория>
   cd PTracker
   ```

2. При необходимости скопируйте файл конфигурации:
   ```bash
   cp .env.example .env
   ```

3. Соберите и запустите контейнеры:
   ```bash
   docker compose up --build -d
   ```

4. Откройте в браузере:
   ```text
   http://localhost:1111
   ```

При первом запуске сервер автоматически:
* Создает структуру таблиц в PostgreSQL.
* Выполняет первичное наполнение (seed): создает администратора, этажи, сотрудников, базовые задачи и инвентарь.
* Сохраняет загружаемые файлы в изолированный том `uploads_data`.

### Остановка
```bash
docker compose down
```

Для полной очистки базы данных и томов используйте:
```bash
docker compose down -v
```

## Локальный запуск для разработки

1. Запустите PostgreSQL локально или в Docker на порту `5432`.
2. Создайте файл `.env` на основе `.env.example`:
   ```env
   DB_HOST=localhost
   DB_PORT=5432
   DB_USER=postgres
   DB_PASSWORD=root
   DB_NAME=ptracker_db
   DB_SSLMODE=disable
   PORT=1111
   SESSION_SECRET=local-development-secret-key-32b
   FNG_API_KEY=""
   ```
3. Выполните первичное наполнение БД (миграция + сидирование):
   ```bash
   go run ./cmd/server/main.go -reset
   ```
4. Запустите веб-сервер:
   ```bash
   go run ./cmd/server/main.go
   ```
5. Приложение запустится на `http://localhost:1111`.

## Руководство оператора (Playbook)

### 1. Интерактивная карта этажей (`#map`)
* **Переключение этажей:** Кликните по вкладкам этажей (например, «1 этаж», «2 этаж») в верхней панели карты.
* **Информация о рабочем месте:** Клик по столу на плане открывает карточку с ФИО сотрудника, его должностью, привязанным оборудованием и списком открытых задач.
* **Привязка задачи к месту:** В карточке рабочего места доступна кнопка быстрого создания задачи, которая автоматически привязывается к выбранному столу.
* **Масштабирование и навигация:** Поддерживается перемещение плана мышью (drag) и колесиком мыши (zoom).

### 2. Канбан-доска задач и заявок (`#board`)
* **Колонки статусов:** «Открыта» $\rightarrow$ «В работе» $\rightarrow$ «На проверке» $\rightarrow$ «Закрыта».
* **Создание задачи:** Кнопка «+ Создать задачу» в шапке. Обязательно укажите заголовок, выберите исполнителя, приоритет, критичность (S1–S4) и при необходимости прикрепите рабочее место.
* **Прикрепление скриншотов:** В форме задачи поддерживается загрузка изображений или вставка скриншота из буфера обмена (Ctrl+V).
* **Фильтры:** Поиск по тексту/номеру задачи (`PT-X`), фильтрация по исполнителю, приоритету и критичности.
* **Раздел «Мои задачи» (`#my-tasks`):** Персональный вид, где автоматически отфильтрованы только те задачи, где текущий пользователь назначен исполнителем.

### 3. Каталог сотрудников и рабочих мест (`#employees`)
* **Поиск:** Живой поиск по имени, должности, отделу, email и номеру телефона.
* **Карточка сотрудника:** Отображает фото, контакты, номер закрепленного стола и выданное оборудование.
* **Редактирование (для администратора):** Возможность изменить должность, отдел или назначить сотруднику другое рабочее место из выпадающего списка доступных этажей.

### 4. Бронирование переговорных и режим планшета (`#rooms`)
* **Обзор занятости:** Карточки переговорных показывают текущий статус («Свободна» / «Занята»), оставшееся время и шкалу бронирований на день.
* **Быстрая бронь:** Кнопка «Забронировать» на карточке позволяет занять комнату на 15, 30 или 45 минут в один клик.
* **Планирование:** Кнопка «+ Забронировать» открывает диалог выбора произвольного интервала времени и темы встречи с автоматической защитой от коллизий.
* **Режим планшета переговорной:**
  * Доступен по адресу: `/tablet/rooms/{code}/?location=inside` (планшет внутри) или `?location=outside` (планшет у двери снаружи).
  * На планшете снаружи доступно создание быстрой брони при свободной комнате.
  * Продление активной встречи разрешено только с планшета, работающего в режиме `inside`.

### 5. Инвентаризация и учет оборудования (`#inventory`)
* **Каталог техники:** Показывает инвентарный номер, категорию, статус («Выдано», «На складе», «В ремонте», «Списано»), привязанного сотрудника и рабочее место.
* **Пакетное добавление:** Кнопка добавления позволяет сгенерировать сразу группу однотипных позиций (например, 10 мониторов).
* **Распознавание документов (OCR):** Кнопка со значком сканера в панели инвентаря открывает модуль распознавания. Поддерживается вставка текста УПД / накладной или загрузка демо-образца с автоматическим парсингом табличных строк.
* **Печать термоэтикеток:** Клик по кнопке со штрихкодом открывает окно печати стикера фиксированного размера с QR/штрихкодом для маркировки оборудования.

### 6. Интерактивный конструктор этажей (`/constructor/`)
* Доступен администраторам через меню профиля или по прямому URL `/constructor/`.
* **Инструменты панели:**
  * **Стена:** Рисование капитальных перегородок с привязкой к сетке.
  * **Стол:** Размещение рабочих мест на плане с генерацией уникального кода.
  * **Метка:** Нанесение текстовых надписей для комнат и зон.
* **Сохранение:** Кнопка «Сохранить этаж» сохраняет все координаты и конфигурацию в базу данных в формате JSON/SQL.

### 7. Сетевой мониторинг (Пингер)
* Доступен администраторам и специалистам ИТ по кнопке «Пингер» в шапке системы.
* Отображает онлайн/офлайн статус устройств, имеющих назначенный IP-адрес.
* Кнопка «Проверить сейчас» принудительно инициирует фоновый опрос хостов без ожидания таймера.

### 8. Учет рабочего времени
* Виджет в левом нижнем углу интерфейса позволяет сотруднику фиксировать рабочий день:
  * Кнопка «Начать день» запускает отсчет рабочего времени.
  * Кнопка «Перерыв» ставит таймер на паузу с накоплением времени отдыха.
  * Кнопка «Завершить день» закрывает рабочую сессию в БД.

## Справка по REST API

### Аутентификация
* `POST /api/auth/login/` — Авторизация (JSON: `{"username": "...", "password": "..."}`). Возвращает подписанную cookie `session_user`.
* `POST /api/auth/logout/` — Завершение сессии и сброс cookie.

### Задачи
* `POST /api/tasks/create/` — Создание задачи.
* `POST /api/tasks/{id}/update/` — Обновление полей задачи.
* `POST /api/tasks/{id}/delete/` — Удаление задачи (возвращает 404, если задача не найдена).
* `GET /api/tasks/events/` — SSE-поток событий реального времени (`task_created`, `task_updated`, `task_deleted`, `room_booked`).

### Переговорные комнаты
* `GET /api/rooms/bookings/?date=YYYY-MM-DD` — Список бронирований на дату.
* `POST /api/rooms/quick-book/` — Быстрое бронирование комнаты с валидацией длительности.
* `POST /api/rooms/bookings/create/` — Создание бронирования на произвольный интервал.
* `POST /api/rooms/bookings/{id}/delete/` — Отмена бронирования.
* `POST /api/rooms/extend/` — Продление текущей встречи (только изнутри).

### Инвентарь
* `GET /api/inventory/` — Получение реестра оборудования с фильтрацией.
* `POST /api/inventory/create/` — Регистрация единицы техники.
* `POST /api/inventory/batch-create/` — Пакетное создание оборудования.
* `POST /api/inventory/{id}/delete/` — Удаление позиции оборудования.

## Эксплуатация и обслуживание

### Просмотр логов контейнера
```bash
docker compose logs -f app
```

### Подключение к PostgreSQL внутри контейнера
```bash
docker compose exec db psql -U postgres -d ptracker
```

### Резервное копирование данных
1. Бэкап базы данных PostgreSQL:
   ```bash
   docker compose exec -T db pg_dump -U postgres ptracker > backup_$(date +%F).sql
   ```
2. Бэкап загруженных скриншотов и медиа-файлов:
   ```bash
   docker cp ptracker_app:/app/web/static/uploads ./uploads_backup
   ```

### Восстановление из бэкапа
```bash
docker compose exec -T db psql -U postgres -d ptracker < backup.sql
```
